# 影刀 RPA 编码模块：规则与环境

SKILL.md 的流程是步骤，本文件是规则与环境。生成函数前读这里；遇到"影刀为什么这样"的问题读这里。

## 代码铁律

- 标识符一律 ASCII，函数名用 `动词_名词` 并可加业务前缀；中文全部放进 docstring 与注释。
- 目标环境 Python 3.10.11（3.7.4 亦可）。签名只写基础注解（`: str`、`-> float`），避开 `X | Y` 与复杂泛型。
- 新函数用普通参数 + `return`；`args` 字典只属于 `main`。
- 纯函数：不读 `glv`、不调 `xbot`、不产生副作用，除非用户当次明确要求。
- 默认参数不用容器（列表/元组/字典）——影刀参数面板会把它拆成多个参数；参数值避免含逗号，逗号会被误拆。
- 输入不合法时抛带中文说明的异常；只包装可预判的错误。
- 第三方包必须在 docstring 里写明装包步骤：影刀右侧「更多」→ 输入 pip 指令 → 每个应用独立装包。
- 关键步骤写中文注释，用大白话解释「这行在干嘛、为什么」。

## docstring 必备八项

按序写明，每项 1-3 行短句：

1. 这个函数做什么（一句人话）
2. 输入（名字、类型、示例值、默认值）
3. 输出（类型、示例值）
4. 调用例子
5. 输入要求，以及不合法时的行为
6. 依赖与装包步骤
7. 运行环境（Python 版本）
8. 影刀里怎么调用（用「调用模块」指令选本函数名、设参数与返回值存储变量）

## 简洁性要求

代码是给人读、给人改、给人粘进影刀的，不是用来展示能力的。

- **只实现用户明确要的输入输出。** 可选参数要能说出具体场景才加。
- **输入校验覆盖真实会发生的情况**，异常类型选最贴切的那个，同一个错误不铺三条分支。
- **列名匹配用字典精确匹配 + 一层兜底**，不为每个指标写独立的查找函数。
- **常量提到模块级**，不在函数体内反复构造同一个集合。
- **注释解释"为什么"**：`# 把反斜杠换成正斜杠` 是废话；`# Windows 下两者等价，顺带避开转义坑` 才有价值。
- **判断标准**：把 docstring 全部删掉，函数是否仍清晰可读？不能，说明逻辑埋得太深。
- **自查行数**：一个"提取几个指标"的函数超过 150 行，或 docstring 超过函数体，先找过度设计。

## 运行环境

- 影刀按应用独立内嵌 CPython：新建应用 3.10.11，旧应用 3.7.4，可手动升级，与本机 Python 无关。
- `xbot` 由影刀主进程运行时注入，属虚拟接口，本机无此包。函数体是普通 Python，剥离壳后可在本机实跑。
- 本机模块 `.py` 为 UTF-8 无 BOM。

## 模块骨架与调用

- 骨架见 `assets/skeleton.py.tpl`；注释块、4 行固定 import、`def main(args): pass` 逐字不可改。
- 「调用模块」指令：选 Python 模块 → 选模块内的函数 → 给函数设置参数（有默认值可不传）→ 设置返回值存储变量。新函数用普通参数 + `return`。
- 「调用流程 / 调用整个模块」只执行 `main(args)`，参数与输出走 `args["..."]`；挂在其后的新函数不会被调用。
- 官方示例即 `def main(args): pass` 与 `def fib(a, b): return a + b` 并存。

## 已知缺陷与规避

- 参数面板把参数值里的逗号误拆。默认值写成元组或列表会被拆成多个参数，字典不会；多值优先打包成一个字典。
- 参数面板解析的是函数签名，注解是签名的一部分。基础注解暂无失败实测；复杂泛型与 `X | Y` 暂不使用。
- 面板里手填 Windows 路径会被写成字符串字面量，反斜杠可能触发 unicodeescape 报错；面板里用正斜杠最稳。

## 依赖与全局变量

- 第三方包：影刀右侧「更多」→ 输入 pip 指令安装；每个应用独立装包，跨应用引入用 `activity_venv_v2.introduce("应用名")`。
- 全局变量读写用 `glv['名称']`；`xbot` 系能力只在影刀编辑器内有效，无需额外 import。

## 工程文件写入（禁止）

- 本地按 uuid 分目录：`%LOCALAPPDATA%\ShadowBot\users\<userId>\apps\<uuid>\xbot_robot`；应用名只在 `package.json` 的 `name` 字段且可重名，不能唯一定位文件。
- 外部直接改 `.py` 会令 `package.sigstore` 失效、Studio 拒开；运行不生效须重启清缓存；可视化生成的重开还原；保存/发版会上传云端。
- 影刀官方 CLI / MCP Server / 开放 API 均不按应用名读写模块 `.py`，官方明确不支持修改应用内部代码。
- 因此本技能永不写回影刀工程文件，只输出代码文本，由用户在影刀编辑器内粘贴并保存，让影刀自行维护签名。

## 需求模糊时的访谈细则

`AskUserQuestion` 发布的选择题，每个问题 2-4 个选项。选项要写成**真实取舍**，不是凑数。

### 好问题长什么样

- **问决策，不问事实。** "表里有哪些列"是事实，你去读；"访客数按店铺口径还是商品口径"是决策，你问。
- **一个问题一个决定。** 复合问题（"取哪个口径、输出什么格式"）拆成两题，用户才好逐个回答。
- **选项写清代价。** description 里说明每个选项会带来什么后果，而不只是选项名。
- **header 用短标签**（最长 12 字符），它是问题卡上的芯片名，太长会被截断。
- **label 不要带前后空格**——它是选项的查找键，带空格会匹配不上。
- **不必列全所有可能**：工具自带"其他"自由输入框，用户总有第四条路。

### 典型决策点

| 决策 | 为什么必须问 |
|---|---|
| 指标口径（如"访客数"对应店铺还是商品） | 选错整个报表数字错 |
| 异常值处理（如"-"转 0 还是报错） | 影响下游统计逻辑 |
| 缺失数据处理（如某指标列不存在时返回 0 还是抛错） | 影响流程是继续还是中断 |
| 输出形态（单值 / 数据字典 / 列表） | 决定函数签名与调用方式 |
| 匹配规则（精确匹配还是模糊包含） | 影响误匹配风险 |

### 不必问的

- 需求已唯一确定实现方式；
- 缺的信息你查一下就有（源文件存在吗、有哪些列、依赖装了吗）；
- 用户明确说过"你看着办"（直接按推荐实现，并在交付时说明用了什么假设）。

## 实跑经验（踩坑记录）

- **xlsx 的 dimension 声明可能错误**：生意参谋导出的文件内部声明 `A1:A1`，`read_only=True` 只会读到第一列，然后误报"缺少指标"。必须用 `read_only=False`。这类问题只有真实实跑能发现——自造 mock 会掩盖正是出问题的那一层。
- **AST 不记录 raw 字符串前缀**：`ast.Constant.kind` 只有 `'u'` 和 `None`，所以"docstring 是不是 r 开头"没法靠 AST 判断，只能看源文件字节。
- **`r"""` 内部不能再出现 `"""`**：否则 docstring 提前截断，后续中文变成代码，报 `invalid character`。
- **交付字节一致性**：曾出现"用 A 文件验证通过、贴给用户的是 B 文本"，B 从未进入验证环节，用户复制即报语法错。根因是写盘工具吞掉反斜杠，而交付文本是重新手敲的。
