# 影刀 RPA 编码模块：环境与调用规则

## 运行环境

- 影刀按应用独立内嵌 CPython：新建应用 3.10.11，旧应用 3.7.4（可手动升级），与本机所装 Python 无关。
- 默认目标 3.10.11，禁用 3.11+ 语法；用户按 `影刀模式 3.7：` 指定时，才按该版本写。
- `xbot` 由影刀主进程在运行时注入，属虚拟接口；本机 Python 无此包。生成结果只能静态检查，不得声称已在影刀运行通过。
- 本机模块 `.py` 为 UTF-8 无 BOM。

## 模块骨架与调用

- 骨架见 `assets/skeleton.py.tpl`；注释块、4 行固定 import、`def main(args): pass` 不可改动。
- 「调用模块」指令：选 Python 模块 → 选模块内的函数 → 给函数设置参数（有默认值可不传）→ 设置返回值存储变量。新函数用普通参数 + `return`。
- 「调用流程 / 调用整个模块」只执行 `main(args)`，参数与输出走 `args["..."]` 字典；挂在其后的新函数不会被调用。
- 官方示例即 `def main(args): pass` 与 `def fib(a, b): return a + b` 并存。

## 已知缺陷与规避

- 参数面板会把参数值里的逗号误拆；默认值写成元组或列表会被拆成多个参数，字典不会。因此默认参数不用容器，多值优先打包成一个字典。
- 「调用模块」参数面板解析的是函数签名，注解是签名的一部分。基础注解暂无失败实测；复杂泛型与 `X | Y` 暂不使用。

## 依赖与全局变量

- 第三方包：影刀右侧「更多」→ 输入 pip 指令安装；每个应用独立装包，跨应用引入用 `activity_venv_v2.introduce("应用名")`。
- 全局变量读写用 `glv['名称']`；`xbot` 系能力只在影刀编辑器内有效，无需额外 import。
- 默认生成纯函数，不碰 `glv` / `xbot`，除非用户当次明确要求。

## 工程文件写入（明确禁止）

- 本地按 uuid 分目录：`%LOCALAPPDATA%\ShadowBot\users\<userId>\apps\<uuid>\xbot_robot`；应用名只在 `package.json` 的 `name` 字段且可重名，不能唯一定位文件。
- 外部直接改 `.py` 会令 `package.sigstore` 失效、Studio 拒开；运行不生效须重启清缓存；可视化生成的重开还原；保存/发版会上传云端。
- 影刀官方 CLI / MCP Server / 开放 API 均不按应用名读写模块 `.py`，官方明确技能不支持修改应用内部代码。
- 结论：本技能永不写回影刀工程文件，只输出代码文本，由用户在影刀编辑器内粘贴并保存，让影刀自行维护签名。

## 交付决策摘要（2026-11-08 共识）

- 触发：显式调用技能或句首「影刀模式」；单轮生效；输入宽松理解、最多反问一句。
- 交付物：一个完整代码块；所有说明集中在 docstring 八项与逐行中文注释，不另写说明书或接入指引章节。
- 标识符 ASCII，中文全在注释；基础注解允许；纯函数；中文报错；命名 `动词_名词`。
- 技能位于用户级目录，不打包分发，不接影刀 MCP / CLI / API。
