为任何 agent 消费的文档而写的参考：一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份借由指针抵达的文档。打包方式不同；写法却相同：同一套杠杆让每一种都可预测，因为 agent 每次运行走的是同一套*流程*，而非产出同一份输出。

当你写的文档是一个技能时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用选择，以及路由型技能。

## 上下文指针（Context pointers）

一个**上下文指针**是 agent 上下文里持有的一条引用，它命名某些上下文之外的材料，并编码抵达它的条件。一个技能的 description 就是其一；`AGENTS.md` 里点名某文档的一行是同一个东西。决定 agent 何时抵达该材料、以及多可靠的，是指针的*措辞*，而非它的目标。一个指向必需材料、措辞却软弱的指针就是一个方差 bug（variance bug）：先打磨措辞，只有打磨不动了才把材料内联。

一个指针做两件事：说明材料是什么，并列出应当触发抵达它的**分支（branches）**（一个分支是文档处理的一个独特情形，因此不同运行走不同路径）。一个总是加载的指针的每一个词，在每一轮都花费代价，因此它比正文更值得修剪：

- **前置首词（Front-load the leading word）**：指针正是在这里做它的触发工作。
- **一个分支一个触发器。** 重命名单一分支的同义词是"一个分支写两遍"；把它们折叠起来，只保留真正不同的分支。
- **剪掉正文已经携带的同一性说明。**

## 两种负载（The two loads）

你加的每份文档和每个指针，都花费两种预算之一：

- **上下文负载（Context load）** 是总是加载的材料对 agent 窗口的代价：一行 `AGENTS.md`、一条技能描述、任何每轮都坐在上下文里、无论是否触发都要花费 token 与注意力的东西。
- **认知负载（Cognitive load）** 是对人类的代价：存在哪些文档、何时该去翻哪一个。人类就是那个索引。这不是一个要最小化的代价：它是人类能动性的价格；把它花在需要人类判断的地方，从不需要的地方移除。

只通过指针抵达的材料，以指针自身那一行作代价，逃脱了上下文负载；完全没有指针的材料，则全部压在认知负载上。

## 信息层级（Information hierarchy）

一份文档由两种内容类型构建：**步骤（steps）**（agent 执行的、有序的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者自由混合：全步骤（一份配方）、全参考（一次评审的规则，即本技能本身），或两者兼有。核心决策是每片内容落在**信息层级**的哪一档——一个按 agent 需要该材料的紧迫程度排序的阶梯：

1. **文件内步骤（In-file step）** 是主层级：agent 做什么，按什么顺序。
2. **文件内参考（In-file reference）** 按需查阅。常常是一个正当的、扁平的同级集合（一次评审的每条规则在同一档），这是好的安排，不是异味。
3. **披露式参考（Disclosed reference）** 被推到单独的文件中，借由上下文指针抵达，只在指针触发时加载。跨度从同文件夹的兄弟文件，到完全外部、可存于任何地方、任何文档都能指向的参考。

下推太少，顶部臃肿；下推太多，你藏起了 agent 实际需要的材料。那股张力就是整个决策。

**渐进式披露（Progressive disclosure）** 是沿阶梯向下的动作（移出主文件、藏到指针后），好让顶部保持清晰可读。它首要不是 token 优化：它是层级被保护的方式。分支是最干净的披露测试：内联每个分支都需要的，把只有某些分支才抵达的推到指针后。当一份文档有步骤时，本应被披露的、文件内的参考会埋没它们，并把"注意到它们"变成抛硬币：这是一个方差杠杆，不只是可读性杠杆。

**同置（Co-location）** 是文件内的搭档：当阶梯决定了*一片内容坐多深*，同置决定了一旦到位*什么坐在它旁边*。把一个概念的定义、规则、注意事项保持在同一个标题下，而非散落各处，这样读一部分就把它邻居也带来了。检验标准：文档读起来应像为 agent 写的文档。成组的材料那样读；散落的材料不那样读。（不同于重复：重复是在两处复述一个意思；散落是把一个意思打碎到许多处。）

**摊大（Sprawl）** 是这里的失败模式：一份文档就是太长，即便每一行都是活的、唯一的。注意力在多余处被摊薄，每一行额外的都是一行要保持相关。解药是阶梯：把参考披露到指针后，并按分支或序列拆分，让每条路径只携带它需要的。

## 步骤与完成标准（Steps and completion criteria）

每个步骤都以一个**完成标准（completion criterion）**收尾——告诉 agent 工作已完成的那个条件。两个属性让它成为杠杆：

- **清晰度（Clarity）**：agent 能分清完成与未完成吗？一个含糊的边界（"已达成了理解"）会招来**过早完成（premature completion）**：在真正完成前就结束步骤，注意力溜向"已完成"。仍在前方可见的步骤（**完成后的步骤 post-completion steps**）提供了拉力；标准的清晰度就是那股阻力。按序捍卫：**先打磨边界**（局部且便宜）；只有当它不可约地模糊*且*你观察到了那种匆忙时，才通过拆分序列把后面的步骤藏起来。藏匿只在跨一个真实的上下文边界时有效（一次交接或一个子代理派发；一个内联调用会把后面的步骤留在上下文里、什么也没清掉）。
- **要求度（Demand）**：它要求多少。"每个被修改的模型都已计入"迫使彻底的工作，而"产出一份变更清单"不会。要求度驱动**跑腿活（legwork）**（agent 在工作内部做的挖掘，潜伏在措辞里，而非作为它自己的步骤写出），且它不以步骤为界："每条规则都被应用"约束一整片扁平参考，正如"每个步骤都做完"约束一条序列，这正是一份全参考文档仍能带一个穷尽性标准的方式。

最强的标准是既可检验、又穷尽的。

## 何时拆分（When to split）

把一份文档拆成两份，会花费两种负载之一，因此只在切分值得时才拆：

- **按序列（By sequence）**：拆开一段步骤，其中"完成后的步骤"诱使 agent 仓促对待它前面的那一步。让它们不在视野里，驱动对当前任务更多的跑腿活。当心反向：合并序列会把每一步后面的步骤暴露给后续，招来过早完成。
- **按调用（By invocation）**，技能专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 首词（Leading words）

一个**首词（leading word）**是一个紧凑概念，已活在模型的预训练里，agent 运行文档时拿它来思考（_lesson 课程_、_fog of war 战争迷雾_、_tracer bullets 示踪子弹_）。它以 token 的形式重复出现、绝不以句子的形式出现，由此累积出一个分布式定义，并用最少的 token 锚定一整片行为，靠招募模型已持有的先验。自己造词也行，只要你定义清楚，但一个编造的词招募不到先验：你用定义 token 付出的，正是预训练词免费给你的；先去找一个已有的词。

它在两处锚定。在正文里，是*执行*：每次这个词出现，agent 都伸手去够同一行为，而在扁平参考内部，它把注意力聚焦到一类要找的东西。在一个指针里，是*调用*：当同一个词住在你的提示词、你的文档、你的代码库里，agent 就把那共享语言链接到材料，并更可靠地抵达它。

寻找用首词重构的机会。一个在三处拼出来的三元组，一个花费一整句来比划一个想法的指针。每个都是一段乞求坍缩成单一 token 的文字：

- "fast, deterministic, low-overhead（快、确定性、低开销）" → _tight_（一个 _tight_ 循环）。
- "a loop you believe in（你信得过的循环）" → _red_，把一个模糊的闸门变成一个二值可观察状态（循环在 bug 上变 _red_，或不变）。

你赢两次：更少的 token，以及一个更锋利的钩子让 agent 把思考挂上去。假设每份文档都载着首词能退休的重述。去找它们。

**否定（Negation）** 是这杠杆旁边的失败模式：用禁令来驾驶会把被禁行为拽进上下文，并让它*更*可用，而非更不可用。_别去想大象_，大象就成了全部；否定是一个弱修饰语，被强激活的概念碾压，于是禁令半读成一条去做那事的指令。提示**正面（positive）**：陈述目标行为（"写一行注释"），这样被禁的那个从未被说出。一条禁令只有当它是你无法正面措辞的硬护栏时才赢得它的位置；即便那时，也要把它与正面目标配对，好让注意力落在要做什么上。

## 修剪（Pruning）

- 让每个意思有**单一事实来源（single source of truth）**：一个权威处所，这样改变行为就是一处编辑。**重复（Duplication）**（同一意思在多于一处）花费维护与 token，并把一个意思在层级上的显要性膨胀到超过它真实的名次。（这是首词的意外反面：首词故意重复的是 token，绝不是意思。）
- **环境（environment）**也是一个事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），而一份重述它的文档是一个**缓存（cache）**：一份查找的副本，只有当查找昂贵时才值得它的负载。缓存 agent 无法靠查看找到的东西：未写下的约定、一个选择背后的理由、任何配置都不坦白的陷阱。把那些"一个文件、一条命令"就能查到的查找留给环境，那里它们不会过时。
- 逐行检查**相关性（relevance）**：它是否仍关乎文档所做的事？一行因从不关乎任务（纯粹铺陈，或一个应被披露的分支）而过时，或因它描述的行为或世界改变而过时。更短的文档更容易保持相关。没有修剪纪律，默认的命运是**沉积（sediment）**：因为"加"显得安全、"删"显得冒险而沉淀下来的陈旧层，直到你必须向下挖穿它们才能找到仍活着的。
- 逐句猎杀**无效操作（no-ops）**：一条模型默认就已遵守的指令，说了等于没说，却照样要付出负载（token 与注意力）。检验（相对默认它是否改变了行为？）是模型相对的，不是读者相对的：两个人对一条 no-op 有分歧，其实是在对默认有分歧，应通过运行文档来解决，而非辩论。当一句话没通过，删掉整句，而不是从中修剪词。这个检验也给首词打分：一个太弱、打不过默认的词（agent 已经够彻底时还说 _be thorough_）就是个 no-op，而修法是更强的词（_relentless 毫不留情_），不是别的技巧。
