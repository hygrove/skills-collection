# 向导（Wizard）

**向导（wizard-zh）**是一个 bash 脚本，一步步引导人类走过一个手工流程——这个流程手工做很繁琐，每次向 AI 重新解释也很繁琐。它打开每个 URL，精确说明要点击和复制什么，捕获那些值，把它们写到该去的地方（`.env`、GitHub 密钥），在每个阶段确认，并显示还剩多少阶段。它可能配置第三方服务、运行一次性迁移，或把项目从一种状态移到另一种状态。

令人愉悦的 UX 已经由 [template.sh](template.sh) 解决：逐阶段进度、确认闸门、跨平台 URL 打开（含 WSL）、隐藏的密钥输入、幂等的 `.env` 更新、`gh secret`/`gh variable` 写入，以及收尾摘要。**你只需界定流程并编写它的各个阶段。** `STAGES` 标记之上的库在每个向导里都相同；这种一致性正是要点：绝不要手写改动它。

向导默认是短暂的：为单次运行而建，保存到 scratch 或 `scripts/` 路径，活干完就删。只有用户想要一条可重复、应留在仓库里的配置路径时才提交它。

## 流程

### 1. 界定流程（Scope the procedure）

理清人类必须采取的每个手工步骤，以及沿途捕获的每个值。先读仓库，不要冷冰冰地问：

- 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的一个值）。
- 对于迁移或切换：当前状态、目标状态，以及两者之间不可逆的操作。

然后向用户展示有序的阶段列表和每个阶段产出的值，并确认：他们可增、可减、可重排。

**完成条件：** 每个阶段都按序命名，且对每个捕获的值你都知道 (a) 人类从哪里获取它，(b) 它写到哪里（`.env`、GitHub 密钥、两者、或哪都不写；有些阶段纯粹是动作），(c) 它是保密的（隐藏输入）还是公开的。

### 2. 描绘每个阶段的路径（Map each stage's journey）

对每个阶段，写出人类遵循的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填哪个变量：例如"仪表盘 → Developers → API keys → 显示测试密钥 → 复制"。在你确实不知道当前 UI 或确切命令的地方，如实说明并问用户或查文档：绝不要编造可能不存在的步骤。

**完成条件：** 每个阶段都能追溯到陌生人可遵循的具体指令。

### 3. 编写向导（Author the wizard-zh）

把 `template.sh` 复制到目标路径。把示例阶段替换成每个步骤一个 `stage`，按依赖顺序。使用库里的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为你写的阶段数。

把模板设定的标准守住：要它的值之前先开 URL，任何保密的都用 `ask_secret`，每个持久化的值都用 `write_env`，只有 CI 真正需要的才用 `set_secret`，任何不可逆操作前都要 `confirm`。每个 `stage` 会清屏，所以只显示当前步骤：把一个阶段保持为一项专注任务，免得人类需要的任何东西滚走。不要碰标记之上的库。

### 4. 验证并交接（Verify and hand off）

- `bash -n <script>`；若可用则运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它：它会开浏览器并阻塞在人工输入上。改为静态追溯：第 1 步的每个值都被捕获并落到第 1 步说的地方，且每个 `set_secret` 名称精确匹配 CI 里的一个 `secrets.*` 引用。
- 告诉用户如何运行它。如果它是可重复的配置路径，就提交它并从 README 链接，这样下一个人跑脚本而不是问 AI。
