# 扩展性思维 · 联想配方库（Expansion Cookbook）

本文件是 `expansive-thinking` 技能的配套参考。作用是把"怎么找到扩展点"从纯靠临场发挥，变成可复用的映射表。每次启用技能时，先按主题命中下表，取 1-2 个最贴合的延伸点；表外主题用 SKILL.md 的"联想引擎"五步法现场推导。

## 使用方式

1. 定位用户问题所属领域。
2. 读该领域的「搭配/前置/混淆/反面」四条，挑与主答案咬合的 1-2 条作为 `🔗 扩展性思维`。
3. 从「常见误区」里挑 2-4 条作为 `⚠️ 避坑指南`。
4. 有对应实操经验时，从「真实项目坑」挑一条作为 `🛠 真实项目中的坑`。

## 营养健康

- 搭配/协同：蛋白质 ↔ 维生素C（胶原合成）、钙 ↔ 维生素D（吸收）、铁 ↔ 维C（非血红素铁吸收）、益生菌 ↔ 膳食纤维（益生元）。
- 前置基础：谈"补剂"前先谈"膳食结构"；谈"减脂"前先谈"热量缺口"这个唯一前提。
- 易混淆对比：维C（水溶性，易缺但可补）vs 维D（脂溶性，过量中毒）；"无糖" vs "无热量"。
- 反直觉另一面：吃够蛋白但若总热量不足，身体会拿蛋白供能而非合成组织。
- 常见误区：① 越多蛋白越好（伤肾）；② 维C 治感冒（仅轻微缩短病程）；③ 晚上吃碳水就胖（看全天总量）。
- 真实项目坑：营养推荐类产品只推单一营养素当卖点，被专业用户指出缺协同维度，专业度翻车。

## 编程 / 前端

- 搭配/协同：TypeScript ↔ 严格 ESLint（类型+约束双保险）；组件化 ↔ 状态管理（规模上来才显价值）。
- 前置基础：学框架前先熟语言特性（如 React 前先懂 JS 闭包/this）。
- 易混淆对比：防抖(debounce) vs 节流(throttle)；`==` vs `===`；受控 vs 非受控组件。
- 反直觉另一面：代码写得"短"不等于"好"；过早抽象比重复更危险。
- 常见误区：① 盲目上微服务（小团队反而更慢）；② 用 `any` 逃避类型问题；③ 把 localStorage 当数据库（容量/安全限制）。
- 真实项目坑：需求分支长期不合并主干，合并日冲突爆量、回归崩一堆——痛定思痛改成"小步快合 + CI 门禁"。

## 编程 / 后端

- 搭配/协同：索引 ↔ 慢查询治理（建了不用=白建）；缓存 ↔ 缓存失效策略（比缓存本身更难）。
- 前置基础：谈高并发前先谈"瓶颈到底在 CPU/IO/锁哪一层"。
- 易混淆对比：进程 vs 线程 vs 协程；乐观锁 vs 悲观锁。
- 反直觉另一面：加机器（扩容）常解决不了根因，反而放大隐性 bug。
- 常见误区：① 在事务里调外部 HTTP（长事务/锁表）；② SELECT * 全表扫；③ 把密码/密钥写进代码仓库。
- 真实项目坑：把密钥提交进 Git 历史，被迫全量轮换密钥+清历史，才上了一键扫描钩子。

## 投资理财

- 搭配/协同：收益 ↔ 风险（永远成对出现）；定投 ↔ 闲钱（用刚需钱定投会被迫割肉）。
- 前置基础：谈收益率前先谈"本金"与"期限"与"通胀"。
- 易混淆对比：年化收益率 vs 累计收益率；波动率 vs 最大回撤。
- 反直觉另一面：分散不是买 10 只同行业基金；低费率长期复利效应被严重低估。
- 常见误区：① 把运气当能力（单边牛市）；② 追涨杀跌；③ 看不懂的产品不碰却偏碰。
- 真实项目坑：用历史最大收益给新人做演示，对方高仓位入场遇回撤恐慌赎回——后改为先讲"最坏回撤"再讲收益。

## 学习 / 效率

- 搭配/协同：输出（教别人/写）↔ 输入（读），费曼学习法；间隔重复 ↔ 主动回想。
- 前置基础：谈"高效"前先谈"睡够 + 专注块"，否则方法是空转。
- 易混淆对比：忙碌 vs 产出；做笔记 vs 真理解。
- 反直觉另一面：休息不是偷懒，是记忆固化必需。
- 常见误区：① 收藏=学会；② 同时 multitask（切换损耗）；③ 只学不练。
- 真实项目坑：列超长待办清单导致决策疲劳啥都没动，改成"每天 3 件要事"后产出反而更高。

## 写作 / 沟通

- 搭配/协同：清晰结构 ↔ 具体例子（抽象结论需落地）；写 ↔ 读 aloud 自检。
- 前置基础：动笔前先想"读者是谁、要他做什么"。
- 易混淆对比：简洁 vs 简略（简略=信息缺失）；客观 vs 中立（中立≠不表态）。
- 反直觉另一面："多写"常不如"删一半"更有力。
- 常见误区：① 开头绕大圈；② 堆术语显专业；③ 一段塞三个论点。
- 真实项目坑：技术文档写满实现细节却没"怎么跑起来"，用户卡在第一步——后来固定加"30 秒上手"段。

## 通用"避坑"话术模板

- 误区 = 「普遍做法 + 为什么错 + 正确做法」三件套，控制在 1 行。
- 真实坑 = 「现象（上线/使用后发生了什么）→ 根因 → 后来怎么规避」，要具体到能让人点头"确实"。
