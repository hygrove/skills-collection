# 加深（Deepening）

在已知一个浅模块簇及其依赖的前提下，如何安全地把它加深。假设已掌握 [SKILL.md](SKILL.md) 中的词汇：**module 模块**、**interface 接口**、**seam 接缝**、**adapter 适配器**。

## 依赖分类

评估一个加深候选方案时，给它的依赖分类。类别决定了加深后的模块如何跨越其接缝被测试。

### 1. 进程内（In-process）

纯计算、内存状态、无 I/O。永远可加深：合并模块，直接通过新接口测试。无需适配器。

### 2. 本地可替代（Local-substitutable）

拥有本地测试替身（Postgres 的 PGLite、内存文件系统）的依赖。只要替身存在就可加深。加深后的模块在测试套件里用替身运行。接缝是内部的；模块外部接口上没有端口（port）。

### 3. 远程但自有（Ports & Adapters，端口与适配器）

你自己的、跨网络边界的服务（微服务、内部 API）。在接缝处定义一个**端口（port）**（接口）。深模块持有逻辑；传输层作为**适配器**被注入。测试用内存适配器。生产用 HTTP/gRPC/队列适配器。

推荐形态：*"在接缝处定义一个端口，为生产实现一个 HTTP 适配器、为测试实现一个内存适配器，这样即使逻辑被部署在网络两端，它也待在一个深模块里。"*

### 4. 真正的外部（Mock）

你无法控制的第三方服务（Stripe、Twilio 等）。加深后的模块把外部依赖当作一个被注入的端口来接收；测试提供一个 mock 适配器。

## 接缝纪律

- **一个适配器意味着一个假设性接缝。两个适配器意味着一个真实的接缝。** 除非至少有两份适配器站得住脚（通常是生产 + 测试），否则不要引入端口。单适配器的接缝只是间接层。
- **内部接缝 vs 外部接缝。** 一个深模块既可以有内部接缝（对其实现私有、供它自己的测试使用），也可以有位于其接口处的外部接缝。不要仅仅因为测试用到内部接缝，就把它们通过接口暴露出去。

## 测试策略：替换，而非叠加

- 一旦在加深后模块的接口处有了测试，浅模块上的旧单元测试就成了废物；删掉它们。
- 在加深后模块的接口处写新测试。**接口就是测试面。**
- 测试通过接口断言可观察的结果，而非内部状态。
- 测试应当能在内部重构后存活，因为它们描述的是行为，而不是实现。如果一个测试在实现改变时必须跟着改，那它就是在测接口之外的东西。
