一个模糊的想法出现了，它太大、一个 agent 会话装不下，还裹着迷雾：从这里到**目的地**的路还看不见。寻路（Wayfinding）要找的是那条路，而不是一头撞向目的地。本技能把这条路绘成问题追踪器上的一份**共享地图**，然后一次解决一个它的**决策工单（decision tickets）**（其解答是一个决策、而非待执行构建切片的问题），直到路线清晰。

目的地因任务而异，为它命名是绘图的第一动作：它塑造每一张工单。它可能是要交接并迭代的一份规格说明、开始规划前就要锁定的一个决策，或是就地做出的一个改动（如数据结构迁移）。地图与领域无关：工程工作、课程内容，任何契合这种形态的东西都行。

## 规划，而非执行（Plan, don't do）

Wayfinder 默认是**规划**：每张工单解决一个决策，当地图清晰（在有人去执行那件事之前已无决策待定）时地图就完成了。那种"直接把活干了"的冲动，通常就是信号——你已抵达地图边缘，是时候交接了。一个任务可以在它的**Notes**里覆盖这一点，把执行也带进地图本身，但缺席时，产出的是决策，不是交付物。

## 按名字引用（Refer by name）

每张地图和每张工单都是一个 issue，因此它有一个**名字**：它的标题。在人类读到的所有东西里（叙述、地图的 Decisions so far 节），都按名字引用它，绝不用孤零零的 id、编号或 slug。一堵 `#42, #43, #44` 是看不懂的；名字一眼可读。id 和 URL 不会消失；名字包裹着它的链接，但它们骑在名字*内部*，绝不作为它的替代。

## 地图（The Map）

地图是此仓库问题追踪器上的一个 issue，打上 `wayfinder-zh:map` 标签，是规范性产物。它的工单是地图的子 issue。

地图是一个**索引**，而非存储。它列出已做的决策，并指向持有其细节的工单；一个决策只存在于唯一一处——它的工单，因此地图从不重复陈述它，只提炼要点并给链接。

**地图、它的子工单、阻塞关系和前沿查询实际存放在哪里，取决于具体追踪器。** 问题追踪器本应已提供给你。如果没有，请告诉用户去运行 `/setup-matt-pocock-skills-zh`。查阅追踪器文档的**"寻路操作（Wayfinding operations）"**小节，了解*该*仓库如何表达它们。如果没提供任何追踪器，默认使用本地 markdown 追踪器。

### 地图正文（map body）

整张地图的低分辨率视图，每会话加载一次。未关闭的工单**不**列出：它们是开放的子 issue，通过查询找到。

```markdown
## Destination 目的地

<抵达这张地图末端是什么样子：这份努力正在寻路前往的规格说明、决策或改动。一两行；每个会话在选择工单前都先以此定位。>

## Notes 备注

<领域；每个会话都应查阅的技能；本任务的常设偏好>

## Decisions so far 已决决策

- [<已关闭工单标题>](link)：<一行要点式的答案>

## Not yet specified 尚未明确

<!-- 见"战争迷雾"：范围内的迷雾，你还无法做成工单；随前沿推进而毕业 -->
```

### 工单（Tickets）

每张工单是地图的一个**子 issue**；追踪器的 issue id 即其身份。它的正文是问题，大小限定在一个 100K token 的 agent 会话内：

```markdown
## Question 问题

<这张工单所解决的决策或调查>
```

每张工单带一个 `wayfinder-zh:<type>` 标签，取值之一：`research-zh`、`prototype-zh`、`grilling-zh`、`task`（见下文"工单类型（Ticket Types）"一节）。

一个会话通过把工单**指派**给驱动地图的开发者来**认领**它，**先于此、在任何工作之前**，这样并发会话会跳过它。那个指派人*就是*认领：一个开放、未指派的工单是未被认领的。

阻塞使用追踪器的**原生**依赖关系：这很关键，因为它能在追踪器自己的 UI 里把前沿*可视化*呈现，让人类无需打开地图就能看见什么可认领。只有缺乏原生阻塞的追踪器才退回到正文约定。当一个工单的所有阻塞工单都关闭时，它就是**未阻塞（unblocked）**；**前沿**是开放的、未阻塞的、未被认领的子工单，是已知世界的边缘。

答案不是正文的一部分；它在解决时记录（见下文"走通地图（Work through the map）"一节）。解决工单时创建的资产从 issue 链接出去，不粘贴进正文。

## 工单类型（Ticket Types）

每个工单要么是 **HITL**（human in the loop，人在回路，与一位为自己发言的人类*一起*工作），要么是 **AFK**，由 agent 单独驱动。一个 HITL 工单只能通过那次实时交流解决；agent 绝不该站在人类那一侧（一个自己回答自己问题的 grilling-zh agent 已经破坏了这一点）。

- **Research 研究**（AFK）：阅读文档、第三方 API，或本地资源（如知识库）以浮现某个决策所等待的事实。由一个调用 Skill 工具传入 "research-zh" 的子代理解决。当所需知识在工作目录之外时使用。
- **Prototype 原型**（HITL）：通过制作一个廉价、粗糙、具体的产物供人反应（大纲、粗糙草稿、桩代码，或 UI/逻辑代码），调用 Skill 工具传入 "prototype-zh"，来提升讨论的保真度。把原型作为资产链接。当"它该长什么样"或"它该怎样表现"是关键问题时使用。
- **Grilling 诘问**（HITL）：对话。默认情形。总是调用 Skill 工具两次，分别传入 "grilling-zh" 和 "domain-modeling-zh"。
- **Task 任务**（HITL 或 AFK）：在做*决策*之前必须发生的手工活：没有可决策、原型或研究的东西，但讨论被它阻塞直到完成。注册一项服务好让它的 API 可被评判、配置访问权限、移动数据好让它的形态可见。这是唯一一个*做*而非*决*的类型，它凭"为决策解除阻塞"赢得位置，而非靠交付目的地。agent 能在哪里单独驱动就在哪里单独驱动（AFK）；否则交给人类一份精确的检查清单（HITL）。工作完成时解决；答案记录做了什么，以及后续工单所依赖的任何事实（凭据位置、新 URL、行数）。

## 战争迷雾（Fog of war）

地图*刻意*不完整：不要绘制你还看不清的东西。在活工单之外是**战争迷雾**：那些你能看出要来、却还钉不死的决策与调查的朦胧视图，因为它们悬在仍开放的那些问题上。解决一张工单会清除它前方的迷雾，把现在可明确表述的东西逐一毕业为新的工单，直到通往目的地的路清晰、没有任何工单剩余。

地图的**Not yet specified** 节就是写下那片朦胧视图的地方：可疑的问题、日后要重访的区域。它是朝向目的地的未探明前沿：这里的一切都在范围内，只是还不够尖锐、做不成工单。写得松散或充分都行，视视图允许程度而定；它同时充当给协作者看的方向标，标示这项努力走向何方。

**迷雾还是工单？** 检验标准是：你现在能否精确陈述那个问题，而*不是*你现在能否回答它。

- **做成工单（Ticket）当**：问题已经尖锐，即使它被阻塞、你还不能着手。
- **留在尚未明确（Not yet specified）当**：你现在还无法那样尖锐地措辞。不要预先把迷雾切成工单大小的碎片：它比工单更粗，当前沿抵达时，一块补丁可能毕业成几张工单，或零张。
- **Not yet specified** 排除已决定的（**Decisions so far**）、已经是活工单的，以及范围之外的（下一节）。

## 范围之外（Out of scope）

迷雾只会朝目的地聚拢。目的地固定了范围，因此超越它的工作**在范围之外**：它不是迷雾，也不属于 **Not yet specified**。它在地图上拥有自己的 **Out of scope** 节：你已自觉排除出*这项*努力的工作。是范围、而非尖锐度，把它送到这里。

范围之外的工作永不毕业（前沿在目的地停下），因此只有当目的地被重绘时它才返回，且作为全新的努力，而非续接。

把某物判定为范围之外是一项定界动作，不是路线上的步骤。当一个已存在的工单结果坐落在目的地之外（绘图时被误判入范围，或被一次解决暴露出来），**关闭它**（一个已关闭工单无疑在边境之外），并在 **Out of scope** 节留一行：要点加为何在范围之外，链接那个已关闭工单。它不进 **Decisions so far**，因为后者记录的是实际走过的路线；一个范围边界不是路线上的步骤。

## 调用（Invocation）

两种模式。无论哪种，**每个会话绝不要解决超过一个工单**，研究类工单除外。

### 绘制地图（Chart the map）

用户带着一个模糊想法调用。

1. **命名目的地。** 调用 Skill 工具两次，分别传入 "grilling-zh" 和 "domain-modeling-zh"，来钉死这张地图正在寻路前往什么：规格说明、决策，还是改动。目的地固定了范围，因此先敲定它。
2. **绘制前沿。** 再次诘问，这次**广度优先**：在整个空间铺开，而非深度钻入任一线程，浮现开放的决策和现在就能迈出的第一步。**如果这没有浮现任何迷雾**（通往目的地的路已经清晰，整段旅程小到一会话就够），你就不需要地图了。停下并问用户想如何继续。
3. **创建地图**（标签 `wayfinder-zh:map`）：填好 **Destination** 和 **Notes**，**Decisions so far** 为空，把迷雾勾勒进 **Not yet specified**。
4. **创建你现在能明确的工单**，作为地图的子 issue，然后在**第二遍**接好阻塞边（issue 需要 id 才能互相引用）。接线把工单分进前沿与被阻塞；任何你还不能明确的东西留在迷雾里：**Not yet specified** 节。
5. **发射研究子代理。** 对你刚创建的每个 `research-zh` 工单，启动一个调用 Skill 工具传入 "research-zh" 的子代理来并行解决它，把发现捕到一条一次性的 `research-zh/<name>` 分支上，并从工单带一个上下文指针。
6. 停止：绘图是一个会话的工作；它手解零个。

### 走通地图（Work through the map）

用户带着一张地图（URL 或编号）调用。工单是**可选的**：没有的话，你挑下一个决策，而不是用户。

1. 加载**地图**：低分辨率视图，而非每个工单正文。
2. 选择工单。如果用户指名了一个，用那个。否则取顺序中的第一个前沿工单。**认领它**：在任何工作前把它指派给自己。
3. 解决它。**按需放大**：按需抓取任何相关或已关闭工单的完整正文；对 `## Notes` 块点名的技能调用 Skill 工具。若有疑问，调用 Skill 工具两次，分别传入 "grilling-zh" 和 "domain-modeling-zh"。
4. 记录解决：把答案作为一条**解决评论**发布，**关闭**该 issue，并向地图的 **Decisions so far** 节**追加一个上下文指针**。
5. 添加新浮现的工单（先创建再接线）；把答案已变得可明确表述的任何迷雾毕业，从 **Not yet specified** 清除每个已毕业的补丁，使它只作为它的新工单存在。如果答案揭示某张工单（这张或其它）坐落在目的地之外，**把它判定为范围之外**，而非在路线上解决它。如果决策使地图其它部分失效，更新或删除那些工单。

用户可能并行运行未阻塞工单，因此要预期其它会话在并发编辑追踪器。
